# Submission requirements

From the platform's submit page (<https://app.sprintd.org/events/sprintd-basel-greentech/submit>, copied 2026-11-20). One submission for all of Ctrl+Free; anyone on the team can edit and submit it. Use "Save draft" for the Saturday draft.

- **Draft:** Sat 21 Nov, 15:00–15:30 ("show what you have so far, rough is fine")
- **Final:** Sun 22 Nov, 08:30

## Form fields

| Field | Required | Platform guidance |
|---|---|---|
| Project title | yes | |
| Slogan | | One line that sells it. Say what it does and for whom. Printed next to your name on the results page. |
| Description | | Cover these four, in this order: 1. the problem, in the case partner's words; 2. your solution; 3. how it works, including what is real and what is mocked; 4. what is next if you had four more weeks. |
| Case | auto | Linked automatically from the allocation. |
| Repository URL | yes | A repository the jury can open. A README with setup steps somebody else can follow. The code you wrote during the sprint, on the default branch. A note naming any AI tool or template you started from. |
| Video pitch URL | yes | Show the thing working. A screen recording with your voice over it beats a slide deck. Unlisted is fine, but it must open without a login. |
| Project ZIP | | Max 500 MB. Anything the jury needs that is not in the repo. Name the files so somebody who has never seen the project can tell what they are. |
| Thumbnail image | | Square, ideally 600×600 px, max 5 MB. A screenshot of the working thing, not a logo. Shown on the results page and leaderboard. |
| Authenticity checkbox | yes | "This is our own work, built during this event, not commissioned or purchased." |

## Things to act on

- **This GitHub repo (`beSaif/digitalheat`) is private.** The jury must be able to open it: make it public, or add the jury, before submitting.
- The README must name the AI tools used (e.g. Claude Code) and any template.
- A video is required, separate from the live pitch.

## Case-specific requirements (from the case brief)

See [case-brief.md](case-brief.md#must-haves-for-a-valid-submission-all-on-the-reference-house). In short: a working demonstrator that runs at least one real job under the scheduler's control, a list of all assumptions, and reproducible measurements or calculations in the repo. A spreadsheet, slides or a simulation alone is not a valid submission.

Live pitch: 5 min including a live demo + 3 min Q&A, Sun 09:00–11:30, room 2.22.
